6. VALIDATOR ARCHITECTURE
--------------------------------------------------------------------------------
- stdlib-only Python 3.12 (mirrors the Builder's conservative style). [VERIFIED]
- Read-only by construction: never opens files for writing; no builder invocation,
  no timestamp updates, no ledger/audit/status/locked-map mutation.
- A Validator class accumulates Finding(error_id, location, message); each check is
  independent and additive (collects ALL failures, not just the first).
- Contracts are repository-driven: it uses each file's own declared allowed_* enums
  and change-ledger policy.required_fields as the source of truth, so it tracks the
  repo's contracts rather than hard-coding parallel copies.
- Public API: validate_repository(root) -> (findings, files_validated); main(argv).
- CLI: python tools/nycif_app/validate_mission_control.py --repo-root . [--json]
  exit 0 = pass (concise summary: files validated + 16 contract categories);
  exit 1 = validation failure (each finding printed with id/location/message; no
  traceback); exit 2 = usage/environment error (hub not found).
